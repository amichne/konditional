---
title: "Declare an enum flag"
description: "Checkout needs three outcomes when it checks product eligibility."
---

Use an enum
for the result so callers can handle each outcome explicitly. The input is a
second enum, `Product`, which the rules use to select the outcome.

For the standalone example, put these declarations in `src/main/kotlin/EligibilityFlags.kt`.

```kotlin
import io.amichne.konditional.context.Context
import io.amichne.konditional.context.fact.FactDomain
import io.amichne.konditional.context.fact.FactSchema
import io.amichne.konditional.context.fact.Facts
import io.amichne.konditional.context.fact.SingleFact
import io.amichne.konditional.core.Namespace

enum class Product { PAYMENTS, LENDING, REPORTING, SAVINGS }
enum class ProductEligibility { NOT_ELIGIBLE, ELIGIBLE, MANUAL_REVIEW }

val productKind = SingleFact("checkout.product", FactDomain.enumeration(Product.entries) { it.name })

data class CommerceContext(val product: Product) : Context {
    override val facts = Facts.of(productKind.value(product))
}

object EligibilityFlags : Namespace("eligibility", factSchema = FactSchema(productKind)) {
    val productEligibility by enum<ProductEligibility, CommerceContext>(
        default = ProductEligibility.NOT_ELIGIBLE,
    ) {
        rule(ProductEligibility.ELIGIBLE, productKind.oneOf(Product.PAYMENTS, Product.REPORTING))
        rule(ProductEligibility.MANUAL_REVIEW, productKind.oneOf(Product.LENDING))
    }
}
```

Payments and reporting qualify. Lending needs review. Savings matches neither
rule and gets the default. [Use the enum result at the call site](/quickstart/evaluate-a-typed-flag).
