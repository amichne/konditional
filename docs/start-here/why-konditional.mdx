---
title: "Why Konditional"
---

A string lookup asks each caller to supply a key, expected type, and fallback.

```kotlin
val enabled = flags.getBoolean("checkout.upsell-enabled", fallback = false)
```

A typo in this key can compile. In Konditional, the namespace declares a Kotlin property and its default.

```kotlin
object CheckoutFlags : Namespace<NoFacts>("checkout", NoFacts) {
    val upsellEnabled by boolean<CheckoutContext>(default = false)
}

val enabled = CheckoutFlags.upsellEnabled.evaluate(context)
```

If the property name changes, the compiler identifies callers that still use the old name. An enum feature also lets the compiler check the branches of a `when` expression.

External configuration still needs runtime checks. [JSON import](/concepts/json-boundary) matches each value to the namespace declaration before it installs the snapshot.
