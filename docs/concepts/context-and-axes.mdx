---
title: "Context and axes"
---

A `Context` supplies the inputs that a feature can inspect.

## Standard context mix-ins

Implement the mix-ins that your rules use.

- `Context.LocaleContext`
- `Context.PlatformContext`
- `Context.VersionContext`
- `Context.StableIdContext`

## Axes for domain-specific targeting

Axes are how you model custom dimensions such as environment, region, tenant,
or product line. Each entry in an enum that implements `AxisValue<T>` is an axis value.

```kotlin
enum class Environment : AxisValue<Environment> {
    DEV,
    PROD,
}
```

Contexts expose axis selections through `axes(...)`, and rules target them
with `constrain(...)`.

## Stable identifiers and rollout

Implement `Context.StableIdContext` for a gradual rollout. The engine uses the stable ID, feature key, and salt to calculate the bucket.
