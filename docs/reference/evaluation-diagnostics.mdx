---
title: "Evaluation diagnostics"
---

`explain(context)` returns the value and the decision for one evaluation. Use the decision to distinguish a default from a matching rule.

Use the flag from [Run your first flag](/quickstart) and import `io.amichne.konditional.api.explain`.

```kotlin
val result = CheckoutFlags.newCheckout
    .explain(Account(Channel.PILOT))
println(result.value)
println(result.decision)
```

## Top-level fields

`EvaluationDiagnostics<T>` includes these fields.

| Field | Meaning |
| --- | --- |
| `namespaceId` | Namespace identity for the evaluation |
| `featureKey` | Feature key inside that namespace |
| `configVersion` | Version from `ConfigurationMetadata`, if present |
| `mode` | Evaluation mode used by the engine |
| `durationNanos` | Timing field for diagnostics |
| `value` | Final typed value returned by evaluation |
| `decision` | Closed set of evaluation outcomes |

## Decision branches

The `decision` field is one of these branches.

| Branch | Meaning |
| --- | --- |
| `RegistryDisabled` | Namespace-wide kill switch forced the default |
| `Inactive` | Flag inactivity forced the default |
| `Rule` | A rule produced the winning value |
| `Default` | No eligible rule produced a value |

## Rule matches

When the decision involves a rule, the diagnostics include a `RuleMatch`
wrapper with:

- `rule`: the structured rule explanation
- `bucket`: the `BucketInfo` used for rollout reasoning

The matched rule includes its `RuleId`, rollout, specificity, and targeting tree.
A `TargetingNode.Facts` node identifies the fact expression with its operators, stable fact identifiers, and operands.
A condition built with `named` appears as `FactSpec.Named` with its label, so the explanation shows the policy name beside its comparisons.

Use `evaluate` when the caller only needs the typed feature value.
